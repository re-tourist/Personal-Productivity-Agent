# M6 — Backend Integration（增量包）

> 这是 **同一个 Personal Productivity Agent 仓库** 的 M6 文件增量。请将 `src/`、`tests/`、`docs/` 合并到仓库根目录，不要另建项目。**先合并 M1～M5**。M6 不包含替换版 M1～M5；尤其依赖 `workflows/approval_session.py` 与 `services/task_store.py`。

## 目标与边界

- ✅ P0：FastAPI HTTP 接口、Pydantic 输入校验、`ainvoke`、`astream` → SSE、M5 审批状态查看与恢复、M4 幂等任务创建。
- ✅ P0：默认全离线、不需要千问 Key；可选启用 M3 Qwen **只读模拟工具**。
- ✅ P0：接口层 Fake Graph 自动化测试；另提供真实 LangGraph 集成测试（需用户本地依赖）。
- 📘 P1：给出 gRPC 接口契约草图，以及 PostgreSQL 迁移设计，**本包未实现可用的 gRPC 服务或 PostgreSQL 接入**。
- ⚠️ 单机、单 Worker、本机回环地址、SQLite 演示。没有成熟的身份认证、租户隔离、限流、跨进程锁等，不能暴露到互联网。

## 2. 启动 FastAPI

```powershell
# PowerShell，项目根目录
$env:PPA_ENABLE_LIVE_QWEN = "0"
$env:PPA_API_TOKEN = "local-dev-secret"   # 本地示例，可自行修改
python -m uvicorn productivity_agent.api.app:create_app --factory --host 127.0.0.1 --port 8000
```

打开 `http://127.0.0.1:8000/docs` 获取 Swagger 自动交互式文档。

普通用户接口在设置 `PPA_API_TOKEN` 后需要请求 Header：`X-PPA-Token: local-dev-secret`。Swagger 页面右上并不会自动出现 OAuth 授权按钮（这里不是 OAuth），在 Swagger 请求编辑器里手动提供 Header 或使用下方 PowerShell 命令即可。**注意**：当前只是一个演示用静态 token，并没有 Thread 归属校验；仅在本机访问。

## 3. 日程检查（复用 M1）

```powershell
$headers = @{ "X-PPA-Token" = "local-dev-secret" }
$calendar = @{
  request = @{
    title = "组会"
    start_at = "2026-11-03T15:00:00+08:00"
    end_at = "2026-11-03T16:00:00+08:00"
  }
  busy_slots = @(
    @{start_at="2026-11-03T15:30:00+08:00"; end_at="2026-11-03T16:30:00+08:00"}
  )
} | ConvertTo-Json -Depth 6

Invoke-RestMethod -Method POST -Uri http://127.0.0.1:8000/v1/calendar/check -Headers $headers -ContentType "application/json" -Body $calendar
```

流式接口：`POST /v1/calendar/check/stream`。用 `curl.exe -N` 查看事件（避免 PowerShell `curl` 别名行为），正文使用相同 JSON。典型事件：

```text
event: progress
data: {"node":"validate_request","status":"completed"}

event: done
data: {"result":{"status":"conflict", ...}}
```

SSE 这里展示**节点进度**，不是模型逐 Token 流式输出。对于 Qwen，M6 的 `/v1/agent/stream` 也展示 Agent 节点/工具的执行进度；逐 Token 模式以后再做。

## 4. 审批与跨重启恢复（复用 M4 + M5）

```powershell
$headers = @{ "X-PPA-Token" = "local-dev-secret" }
$body = @{title="准备组会"; due_at="2026-12-10T15:00:00+08:00"} | ConvertTo-Json
$draft = Invoke-RestMethod -Method POST -Uri http://127.0.0.1:8000/v1/tasks/drafts -Headers $headers -ContentType "application/json" -Body $body
$draft

# 保存返回的 thread_id，用于查询和批准
$id = $draft.thread_id
Invoke-RestMethod -Method GET -Uri "http://127.0.0.1:8000/v1/tasks/drafts/$id" -Headers $headers

# 此时可关闭 uvicorn 再重启：使用同一个 $id 查询和恢复
$approval = @{approved=$true} | ConvertTo-Json
Invoke-RestMethod -Method POST -Uri "http://127.0.0.1:8000/v1/tasks/drafts/$id/decision" -Headers $headers -ContentType "application/json" -Body $approval
```

必须保留 `thread_id`。不同进程运行时需要保持 `.ppa-data/m6-checkpoints.sqlite` 和 `.ppa-data/tasks.sqlite` 两个数据库文件不被删除。M5 CLI 默认使用的是 `m5-checkpoints.sqlite`，所以 M6 不会自动继承旧 CLI 的 Thread；它使用独立的 M6 Checkpoint DB，但**共用 M4 业务任务数据库**。


调用 `POST /v1/agent/ask` 或 `POST /v1/agent/stream`，请求体：

```json
{"message":"查询明天有哪些待办事项","reference_now":"2026-11-02T18:00:00+08:00"}
```

**注意**：M3 `ToolAgentState` 目前没有挂 Checkpointer，所以这个在线 Demo **不是** M5 的持久化聊天会话；M6 只是把它开放成可调用接口。M3 的本地模拟工具默认只读，`max_model_calls=4`，不会写入实际账户；产生千问 Token 费用。

## 7. 设计限制与后续迁移

1. **并发与状态一致性**：当前每个 Thread 的 `asyncio.Lock` 只能保护一个 Python 进程；多 Worker 或多实例时需要共享锁/任务队列/数据库事务约束。绝不能将 `--workers 4` 当作无成本扩容。
2. **权限**：Thread ID 不是访问令牌，演示 token 不做每用户权限认证。上公网前必须增加真实身份认证、资源归属校验和审计日志。
3. **PostgreSQL**：生产环境建议分别迁移 LangGraph Checkpoint 到 `AsyncPostgresSaver`（包 `langgraph-checkpoint-postgres`）及任务业务表（如 `asyncpg`/SQLAlchemy）。需要迁移 schema、事务处理与数据清理策略；仅改变连接字符串不够。
4. **gRPC**：`docs/grpc-interface.proto` 给出未来内部 RPC 的契约草图；无 server/client 运行代码。gRPC 可以在内部服务间用 Protobuf 提供显式的类型接口，但本项目现阶段没有必要双协议部署。
5. **可靠性**：客户端断开 SSE 可能取消当次流任务，所以流式接口当前仅用于只读工作流。写操作走普通审批 POST，数据库幂等操作可被检查；后台任务队列与可恢复作业是后续可扩展方向。
6. **API 安全**：未加入配额、租户隔离、限流、CORS 策略、分布式 Tracing、监控、密钥轮换等。不要声称生产就绪。

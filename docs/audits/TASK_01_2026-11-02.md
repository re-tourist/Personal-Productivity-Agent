整体层次适合本地单用户作品集，复杂度较小，无证据支持完全重写。`domain → workflows/services → API` 的职责基本清晰，Mock 与 SQLite 是两种不同存储边界，不应为了统一命名强行合并。

| 链路 | 核查结果与源码位置 | 实测覆盖 / 限制 |
|---|---|---|
| M1 State / Graph | `domain/state.py` 定义输入、可选补丁和结果；`workflows/calendar.py` 的局部更新与条件路由匹配，复用纯领域区间运算 | 9 项日程测试，真实 StateGraph；无日历写入 |
| M2 → M1 | `workflows/natural_language.py` 用 Protocol 注入提取器，经 ScheduleIntent 校验及归一化，再调用 M1 | 3 项真实图 + Fake Extractor，5 项意图单测；非在线模型验证 |
| M3 ToolNode | `workflows/tool_agent.py` 用 MessagesState 消息 reducer、bind_tools、tools_condition；默认只读，最多每轮两工具，模型调用预算有界 | 4 项 Fake Model + 真实 ToolNode 测试；工具结果返回模型已覆盖 |
| M4 事务 / 对账 | `services/task_store.py:102` 在 `BEGIN IMMEDIATE` 内写 task 与 operation 索引；`:136` commit 后才注入 ambiguous timeout。`workflows/reliable_task.py` 对账后决定重试 | 6 Graph、8 Store、1 Tool、1 Replan；幂等碰撞、并发、提交前失败及提交后对账均覆盖 |

LangGraph 官方约定确认：同 thread_id 恢复，Command 的 resume 值交给 interrupt，恢复会从节点开头重执行。当前审批设计符合该约定。[官方 interrupts 文档](https://docs.langchain.com/oss/python/langgraph/interrupts)。运行结果仍以本机版本和测试为准。

副作用与边界：

- HTTP 默认不启用 Qwen，`api/app.py:188` 明确 `allow_mock_writes=False`；审批前业务库无任务，拒绝不写入的真图测试通过。
- `tools/reliable_task.py` 是可信调用者显式传入 operation_id 后开放的写工具；它本身不验证审批授权。`demo_m4.py --live` 会显式接入此工具，不能把它宣传成所有入口都强制走 M5；本轮没有执行。当前 HTTP 没有暴露该写工具。
- `api/app.py:276` 每次草稿 POST 都生成新 thread_id / operation_id；同草稿审批重放有保护，但客户端丢失首次草稿响应后重发会产生新草稿。没有验证跨请求草稿创建幂等，不将存储幂等扩大成完整 HTTP Exactly-Once。
- token 是可选演示口令，不是用户身份；未做多租户。thread locks 不跨进程且无清理机制，适合当前单进程范围，非生产并发保障。

## 故障复现、定位、最小修复

1. HTTP提交成功但响应丢失：测试中间件先执行真实 PATCH/SQLite commit，再延迟0.5秒响应；
   客户端读超时设置0.15秒。客户端实际收到 transport_unknown，不能按超时报失败或再次覆盖。
   最小处理在统一 execute 分支：查同一 operation_id → 比对请求 → GET任务 → 比对操作快照，
   能证明已提交且当前一致才返回 updated。Agent 回归断言只发一次 PATCH、version仅增加一次。
   延迟发生于本地测试服务，不是企业API事故。
2. 提交前超时/503：分别延迟且不写入、直接503。对账不存在操作，返回 needs_review，不误报成功。
   三种注入都保留 request_id/thread_id/operation_id 与 HTTP状态/耗时/错误类别，见 pytest.log。
3. 新增跨午夜测试发现“今晚十一点”原离线规则按11点上午解释，从而错误要求未来时间。
   最小修复仅为“今晚”补上晚间小时语义；原23点→次日1点断言及重启用例保留并回归。
4. 测试代码曾因新增日志断言漏导入 json 出现3 failed/4 passed；补导入，未删除或弱化断言。
